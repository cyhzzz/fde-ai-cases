# 样板场景 01 · 询价 → 报价依据

> **对应场景**：Q01 询价信息校验 → Q02 销售自助估价 → Q05 工况选型 → Q07 成本区间 → Q08 三档报价
> **用途**：演示"**文件怎样进来 — 中间怎样判断 — 结果怎样交付**"这条完整链路
> **重要声明**：本目录中所有客户信息均为**虚构脱敏**；所有工程系数、价格系数均为**占位符号**，标注为 `【占位】`，**不可用于任何真实报价**

---

## 一、这条链在演示什么

```
① 文件怎样进来
   01-输入·客户询价单-脱敏样例.md
   （模拟销售从客户处收到的原始信息——注意它是残缺的、口语化的、格式不统一的）
        ↓
② 中间怎样判断
   02-规则·工况选型判断规则表.md
   （把老工程师脑子里的判断，拆成"参数 → 条件 → 输出"的可核对表格）
        ↓
③ 结果怎样交付
   03-交付·询价信息校验单.md      ← 第一阶段交付物（缺什么、要问什么）
   04-交付·选型与报价依据.md      ← 第二阶段交付物（怎么选的、为什么是这个价）
   05-表格·标准工况收集表.csv     ← 可直接发出去的收集表
   06-表格·选型与成本测算.csv     ← 可直接继续流转的测算表
```

**关键设计**：输入文件**故意做成残缺的**——风量没给、粉尘成分没给、场地尺寸没量。这正是真实询价现场的样子，也是 Q01 存在的理由。**一个只在信息齐全时才能工作的系统，解决不了任何真实问题。**

---

## 二、和演示网页的对应关系

网页 `index.html` 的「实战场景」板块里有一个可拖动的「工况参数 → 选型建议」互动模块。本目录的 `02-规则` 与它用的是**同一套判断逻辑与同一组参数**，可以对照着看：

| 参数 | 网页互动模块 | 本目录规则表 |
|:---|:---|:---|
| 处理风量 | 20,000 — 300,000 m³/h 可拖 | 从工况推算 |
| 烟气温度 | 60 — 300 ℃ 可拖 | 决定系列与滤材 |
| 入口粉尘浓度 | 2 — 50 g/m³ 可拖 | 修正过滤风速 |
| 目标排放限值 | 30 / 20 / 10 mg/m³ | 决定滤料等级与清灰方式 |

## 三、怎么用这份样板

**给管理层看**：直接看 `04-交付·选型与报价依据.md`。它展示的是"以前要三天、现在一小时内出来的一份东西长什么样"。

**给技术负责人看**：看 `02-规则·工况选型判断规则表.md` 的**表格结构**。这份表的价值不在里面的数字（数字是占位的），而在于**它把判断过程拆成了可以逐行核对、逐行修改的形式**。蓝威要做的，是用自己的历史项目数据把这个表的每一行填成真实的。

**给一线同事看**：看 `01-输入` 和 `03-交付`。这两份合起来说明一件事——**AI 的产出不是一段话，是一份能直接发出去的清单/一份能继续流转的表。**
