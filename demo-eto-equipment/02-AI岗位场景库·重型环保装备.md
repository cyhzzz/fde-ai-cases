## 〇、这份库和上一份报告的关系

上一份报告回答的是**"AI 该往哪使劲"**，产出六个方向。
这份场景库回答的是**"具体谁、在哪个动作上、AI 接手哪一段"**，产出 40 个可核对的场景。

**两处关键改动**：

**改动一：入口从"能力"换成"岗位"。**
原报告的六个方向是按职能切的（售前 / 设计 / 市场 / 国际 / 售后 / 品牌）。这次换成从蓝威真实岗位出发，逐岗追问四件事——**接收什么材料、做什么判断、结果交给谁、哪一步卡住**。换入口后立刻暴露一个事实：原报告 3.1 里其实已经写到「采购部询价核实材料成本 → 财务汇总总价」，但**采购、财务、PMC、工艺、品质、项目管理这六个岗位，在六个方向里一次都没作为主角出现**。订单是靠这些岗位交付的，不是靠方向交付的。

**改动二：用三条筛子做减法。**
原报告是"六个可以做"；这份库是"四十个值得做"，外加一份**明写了剔除理由**的清单——包括把原报告的方向六「品牌内容与短视频获客」移出场景库（理由见 §7.3）。

## 一、方法：三条筛子与一个判据

### 1.1 三条筛子（减法标准）

一个候选场景要进入场景库，必须先过这三关：

| # | 筛子 | 具体问法 |
|:--:|:---|:---|
| ① | **判断是否重复** | 它的底层判断逻辑，是否已经被库里另一个场景覆盖？重复的合并，不为凑数单独立项 |
| ② | **核心动作是否必须现场完成** | 如果这件事的关键步骤只能由人在现场做（测量、装配、焊接、开机调试），AI 接手的只剩录入——不硬包装成 AI 场景 |
| ③ | **输入/判断/交付物是否说得清** | 说不清"数据从哪来、判断条件是什么、交付的是什么文件"的，不进库 |

### 1.2 一个判据：什么算"一个场景做完了"

这是整套方法里最实用的一条。**不等于写清了痛点，而是三段都成立**：

```
文件怎样进来  →  中间怎样判断  →  结果怎样交付
   ↓                  ↓                  ↓
输入要接近             判断要有依据            输出要像企业里
客户手里的             （数据来源、            真正会继续
真实文件               判断条件、              流转的东西
                       例外处理、              （不是一段话，
                       谁最终确认）            是一份表/报告/通知）
```

按这个判据回头审视原报告的六个方向——**它们停在了"做法"层**。例如方向一写的是"建库、配引擎、联实时价格"，是做法不是规则；方向二写的是"图纸智能解析、参数化改单"，也一样。**"什么工况配什么设备"这条最值钱的规则，至今没有被拆成一张可核对的表。** 这份库的 §6 就是补这一刀。

### 1.3 验证状态标注

每条场景都标了验证状态，对应三种可信度：

| 标记 | 含义 |
|:---|:---|
| 【公开事实】 | 蓝威的公开信息（官网、政府报道）直接支撑该场景存在 |
| 【行业已验证】 | 非标装备/离散制造已有可查的落地先例，蓝威属同构场景 |
| 【推演假设】 | 基于行业共性推演出来的，**必须经蓝威一线确认后才能采用** |

**没有任何一条标注为"已在本企业验证"** —— 因为这次没有做现场访谈。这是这份库当前最大的短板，也是 §9 待确认清单存在的原因。

## 二、蓝威岗位链路图

先看订单在蓝威内部怎么走，再看每个岗位卡在哪。

```
【售前段】
  客户询价 ──→ 销售受理 ──→ 技术报价（老工程师估料估工）
                  │              │
                  │              ├──→ 采购询价核成本
                  │              └──→ 财务汇总定价
                  ↓
              报价与方案交付 ──→ 中标 / 签约

【交付段】
  项目立项（PM）──→ 深化设计（研发设计 10余人）
                        │
                        ├──→ 工艺准备（工艺工程师：下料/折弯/卷板/焊接/装配）
                        │
                        └──→ 采购下单（钢材、滤袋、电机、脉冲阀、风机、减速机）
                                │
                                ↓
                        排产与齐套（PMC）──→ 制造（车间）──→ 检验（品质）
                                                                    │
                                                                    ↓
                                                        发运 ──→ 现场安装调试 ──→ 验收

【服务段】
  售后与备件（服务工程师，覆盖全国 + 7 个海外市场）
        │
        └──→ 复购 / 改扩建（回到售前段）

【贯穿全链】
  财务与成本（项目毛利、成本归集） ｜ 管理层（政策窗口、产能决策、出海节奏）
```

**这张图暴露的三件事**：

1. **报价链上有四个岗位在接力**（销售 → 技术报价 → 采购 → 财务），任何一环慢，整条链慢。原报告只把这条链归给了"售前"。
2. **交付段最短的一块板决定交期**。蓝伽新厂投产后产能翻倍，但 PMC、工艺、采购这三个岗位的工作方式如果没有变化，交期压力会全部传导到那 10 余人的设计团队身上。
3. **服务段是唯一"做完还能再赚一次"的段落**（备件、维保、改扩建），也是知识回流的第一现场。

## 四、减法记录：被砍掉的 20 条

一个场景库的价值，一半来自它收进来的东西，另一半来自它**敢扔掉什么**。

| Q40 复购预警 | 存量客户改扩建机会识别 | 改扩建是复购信号里最强的一类 |

### 4.2 因"必须现场完成"或"说不清"而剔除的 5 条

| 被剔除 | 触犯哪条筛子 | 具体理由 |
|:---|:---|:---|
| **C26 排产计划生成与插单重排** | ② + ③ | 排产的判断必须建立在**实时**的工位负荷、在制进度、设备状态上。蓝威当前没有这个采集基础，AI 生成的排产表**看着合理但落不了地**——这正是筛子③要拦的东西。**降级为 Q18 产能负荷识别，只做"看得见"，不做"派得动"** |
| **C42 预测性维护** | ② | 前置条件是设备联网回传运行数据（风量、压差、温度）。蓝威出货设备是否具备联网条件，公开信息无法确认。**列为条件具备后再议，不是现在做不了** |
| **C06 竞品对标与差异化说明** | ③ | 竞品报价、成本结构均无公开数据。硬做只能靠模型编造数字，而这是**对客材料**，编造的代价是丢单甚至法律风险 |
| **C57 展会/竞品情报** | ③ | 信息主要来自展会现场交流与销售口述，**没有可复现的输入源**；交付物是"情报"这样一段描述，不是企业内部会继续流转的文件 |
| **C58 品牌内容与短视频获客** | ① + ② + ③ | 见下节专论 |

### 4.3 专论：为什么把"品牌内容"移出场景库

原报告方向六「品牌内容与短视频获客」是六个方向里**唯一被完全移出**的一条。三条筛子逐条对：

| 筛子 | 判定 |
|:---|:---|
| ① 判断是否重复 | 它的服务对象是市场部动作，不在"订单 → 交付"的岗位链路上，与库内任何场景都不同源，也接不上任何岗位的日常动作 |
| ② 核心动作是否必须现场完成 | 拍摄、讲解、客户授权沟通都必须现场完成，AI 只能接手"脚本与剪辑"，占比很低 |
| ③ 输入/判断/交付物是否说得清 | **说不清。** 原报告自己写了"要不要网感、要不要人设，取决于蓝威想触达的是采购经理还是老板——这个判断需要蓝威管理层给方向"。**一句连自己都承认判断未定的场景，不该混在场景库里** |

**移出不等于不重要。** 它只是**性质不同**：场景库管的是"把订单变成利润"的效率问题，品牌内容管的是"让客户主动找上门"的认知问题。前者可以按规则核对，后者必须先有品牌策略。**两者混在一起，会让场景库的边界失真。**

> 建议：品牌内容作为一份**独立的品牌营销命题**单独立项，等管理层明确"要触达谁、要不要人设"之后再谈工具，不进本库。

## 五、定稿场景库（40 条）

**卡片格式说明**：每条含输入、判断规则、交付物、卡点、人机分工、待确认六项。**"待确认"一栏是本库最重要的部分**——它标明了哪些地方是我们推演的，需要蓝威一线用真实材料核对。

### 岗位一 · 销售与售前

#### Q01 · 询价信息完整性校验与追问清单
**难度** 低 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：客户来电/微信/邮件的原始需求描述；客户提供的工况参数表（常有缺失）
- **判断规则**：对照《标准工况清单》逐项核对——风量、烟气温度、粉尘成分与浓度、场地尺寸与限高、当地排放限值、供电与气源条件、是否含土建与管网、期望交期。**缺项 → 标记为"必须回问"；模糊项 → 标记为"需二次确认"**
- **交付物**：①询价信息校验单（齐全/缺失/模糊三色标记）②追问清单（按客户能听懂的话改写，附一句话说明"为什么要问这个"）
- **卡点（现状）**：销售不是技术出身，不知道要问什么；等到技术部接手才发现缺料，再回头找客户，来回三四轮
- **人机分工**：AI 负责核对与生成追问话术；销售负责发起追问并判断客户配合意愿
- **待确认**：蓝威现行的《工况收集表》长什么样？有多少项？历史上哪几项最常缺失？

#### Q02 · 销售自助快速估价（区间报价）
**难度** 低 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：Q01 校验后的工况参数（哪怕不完整，只要核心三项齐全）
- **判断规则**：核心参数 → 过滤面积 → 按单位造价区间出投资量级；**输出的是区间，不是点值**，并强制标注"未含土建、管网、安装"
- **交付物**：一页式估价卡（配置要点 + 参考投资区间 + 议价空间提示 + 三个必须说明的前提）
- **卡点（现状）**：客户随口问"大概多少钱"，销售只能去催技术部，技术部正忙着做正式方案——高价值人力被"随口一问"占用
- **人机分工**：AI 出区间与话术；**销售必须口头声明"这是量级估算，正式报价以技术方案为准"**
- **待确认**：蓝威是否允许销售对外给出区间？管理层对这个风险的容忍边界在哪？

#### Q03 · 老客户设备档案速查
**难度** 低 ｜ **见效** 快 ｜ **验证状态** 【公开事实】（1000+ 家客户）

- **输入**：客户名称（或模糊线索："河北那家做铝灰的"）
- **判断规则**：名称/地域/行业 → 匹配历史客户档案 → 输出该客户全部已购设备清单（型号、参数、出厂年份、历次服务记录）
- **交付物**：客户设备档案卡（一页看全）
- **卡点（现状）**：1000+ 家客户，销售换人、客户换人，改扩建时没人说得清"上次买的是什么配置"
- **人机分工**：AI 检索与汇总；销售核对
- **待确认**：历史客户资料目前存在哪（ERP / Excel / 纸质台账）？电子化程度如何？

#### Q04 · 客户项目成熟度分级
**难度** 中 ｜ **见效** 中 ｜ **验证状态** 【推演假设】← 需重点核对

- **输入**：历次沟通记录、客户提供的资料完整度、是否已立项、是否见过决策人
- **判断规则**：五个可判定信号——是否已立项、是否有明确预算、是否见过最终决策人、技术资料完整度、是否设定时间节点。命中数 → A/B/C 三级
- **交付物**：项目分级标签 + 资源投入建议（A 级派工程师，C 级只发标准资料）
- **卡点（现状）**：分不清真项目与陪标/比价，工程师的时间被无效项目吃掉
- **人机分工**：AI 打分与建议；**销售必须能推翻 AI 的评级**
- **待确认**：**⚠️ 这一条最依赖前提条件**——蓝威是否把沟通记录留存在系统里？如果没有 CRM 或类似记录，输入源不存在，本场景**应先挂起**

### 岗位二 · 技术报价

#### Q05 · 工况 → 选型配置生成
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】｜ **全库最核心的规则资产**

- **输入**：工况参数（风量、烟气温度、入口粉尘浓度、目标排放限值、场地尺寸）
- **判断规则**：**拆成"标准模块 + 可变参数"**。核心规则示例（完整版见 `场景库/样板01-询价报价/02-工况选型判断规则表.md`）：

  | 判断条件 | 输出 |
  |:---|:---|
  | 烟气温度 ≥ 200℃ | LSGM 系列（高压脉冲耐高温型）+ PTFE 覆膜玻纤针刺毡 |
  | 130℃ ≤ 温度 < 200℃ | LSDM 系列（低压脉冲长袋）+ P84 聚酰亚胺 / PTFE 覆膜 |
  | 温度 < 130℃ | QMC 系列（气箱脉冲）+ 涤纶防静电针刺毡 |
  | 过滤风速基准 1.0 → 高温 −0.2 / 中温 −0.1 → 高粉尘再 −0.15 | 修正后的过滤风速 |
  | 过滤面积 = 风量 ÷ (风速 × 60) | 过滤面积 m² |
  | 箱体数 = ⌈过滤面积 ÷ 600⌉，最少 2 室 | 箱体数量与脉冲方式 |

- **交付物**：选型配置单（系列 + 过滤面积 + 箱体数 + 滤袋材质 + 达标要点）
- **卡点（现状）**：整套选型判断锁在少数老工程师脑子里；新人半年摸不清门道；老工程师一休假，报价就停
- **人机分工**：AI 出候选配置与依据；**工程师逐项复核并对最终选型签字**
- **待确认**：⚠️ 上表的阈值是**公开工程经验整理，不是蓝威的选型口径**。必须用蓝威历史项目的"工况 → 实际选型"配对数据反推校准。**校准之前，这张表只能用于演示，不能用于报价。**

#### Q06 · 相似历史项目检索
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：本次工况参数
- **判断规则**：按工况相似度（风量、温度、粉尘特性、行业、地域）排序历史项目，而非按时间排序
- **交付物**：相似项目 Top 5 清单（含当时的配置、报价、实际成本、交付周期）
- **卡点（现状）**：只能靠"我记得好像做过类似的"，然后翻文件夹
- **人机分工**：AI 检索排序；工程师判断哪几个真的可参照
- **待确认**：过去 3—5 年项目资料的电子化程度？报价单与实际成本是否都留档？

#### Q07 · 材料清单与成本区间（行情联动）
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：选型配置单（Q05 输出）+ 最新供应商报价 + 钢材等大宗行情
- **判断规则**：标准模块 → 材料清单（板材、型材、滤袋、电机、风机、脉冲阀、减速机）→ 关联**报价时点**的行情与供应商最新价 → 输出成本区间
- **交付物**：成本明细表（分项 + 区间 + 取价日期 + 价格来源标注）
- **卡点（现状）**：**用三个月前的历史价格报价**，钢材一涨，接一单亏一单
- **人机分工**：AI 汇总与联动；采购负责核实关键项行情
- **待确认**：主要供应商是否愿意提供电子报价？现行取价方式是什么？

#### Q08 · 三档报价 + 成本红线校验
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：成本明细表（Q07 输出）+ 项目难度、客户类型、竞争态势、付款条件
- **判断规则**：①生成保守/标准/进取三档；②**成本红线校验——任何一档低于成本下限即报错拦截**；③偏离项清单（哪些客户要求我方未完全满足，需在报价中声明）
- **交付物**：报价单（三档）+ 报价说明 + 技术偏离项表 + 成本红线校验结果
- **卡点（现状）**：人工加利润，来回修改；报高丢单、报低接一单亏一单
- **人机分工**：**AI 只出草稿与区间，最终报价必须由人确认。** 这不是限制，是设计要求
- **待确认**：蓝威的报价审批层级？成本红线的判定权在谁手上？

### 岗位三 · 研发设计

#### Q09 · 历史图纸与资料自然语言检索
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】｜ **建议最先试点**

- **输入**：自然语言提问（"上次河北那家 8 吨回转炉的筒体板厚是多少"）
- **判断规则**：语义解析 → 匹配项目/设备/部件 → 返回原文出处与图纸位置
- **交付物**：检索结果（答案 + 出处链接 + 相关文件清单）
- **卡点（现状）**：10 余人设计团队，大量时间花在翻历史图纸、找相似结构上
- **人机分工**：AI 检索；工程师判断是否可复用
- **待确认**：⚠️ 图纸以什么格式存储（DWG / PDF / 纸质）？是否有 PLM 或共享盘？

#### Q10 · 图纸解析 → 零部件特征与成本
**难度** 高 ｜ **见效** 中 ｜ **验证状态** 【行业已验证】

- **输入**：零部件图纸 / 三维模型
- **判断规则**：识别材质、尺寸、板厚、孔径、公差、表面处理 → 匹配工艺（激光切割/折弯/卷板/焊接）→ 核算硬件成本
- **交付物**：零部件特征清单 + 加工成本核算表
- **卡点（现状）**：手工拆解易漏算错算，且是纯粹的低价值重复劳动
- **人机分工**：AI 提取与核算；工程师复核
- **待确认**：**设计数据安全是硬约束——本场景必须本地部署或私有云，图纸不出内网**

#### Q11 · 参数化改单（BOM / 工时 / 成本联动）
**难度** 高 ｜ **见效** 中 ｜ **验证状态** 【行业已验证】｜ **ETO 模式的命门**

- **输入**：原项目 BOM + 客户变更要求
- **判断规则**：参数变更 → 联动更新受影响的零部件、工艺工时、成本明细，**并完整留存修改轨迹**
- **交付物**：新版 BOM + 工时变更表 + 成本变动表 + 修改轨迹日志
- **卡点（现状）**：一台设备数百上千个零部件，改一个参数要人肉追踪全链条
- **人机分工**：AI 联动生成；工程师确认变更范围
- **待确认**：现有 BOM 是几层结构？用什么工具维护（Excel / ERP / PLM）？

#### Q12 · 设计变更影响分析表
**难度** 中 ｜ **见效** 中 ｜ **验证状态** 【行业已验证】

- **输入**：变更前后图纸/BOM 差异
- **判断规则**：差异 → 受影响的采购项、在制工单、已到货物料、已完工序 → 量化增量工时与物料损耗
- **交付物**：变更影响分析表（影响面 + 增量成本 + 责任归属建议）
- **卡点（现状）**：变更带来的损耗无法实时量化，**项目做完才知道盈亏**
- **人机分工**：AI 出分析表；PM 与设计共同确认
- **待确认**：变更成本目前如何核算？有没有向客户主张变更费用的先例？

#### Q13 · 图纸规范校验（审图）
**难度** 高 ｜ **见效** 慢 ｜ **验证状态** 【推演假设】｜ **建议后置**

- **输入**：设计完成的图纸
- **判断规则**：板材规格是否为国标常备规格、公差标注是否完整、焊接符号是否规范、关键尺寸链是否闭合
- **交付物**：审图意见单（问题清单 + 等级 + 修改建议）
- **卡点（现状）**：审图依赖资深工程师，是设计流程的又一道人头关卡
- **人机分工**：AI 出初审意见；**审图责任始终在持证工程师**
- **待确认**：⚠️ 判断规则的权威来源是什么（企业标准 / 行业标准 / 客户要求）？**规则来源不明确前不建议启动**

### 岗位四 · 工艺

#### Q14 · 工艺路线与工时定额生成
**难度** 高 ｜ **见效** 中 ｜ **验证状态** 【行业已验证】

- **输入**：设计图纸 + BOM
- **判断规则**：图纸特征 → 工序链（下料 → 折弯 → 卷板 → 焊接 → 机加 → 喷涂 → 装配）→ 参照历史同类件的实际工时给出定额区间
- **交付物**：工艺路线卡 + 工时定额表
- **卡点（现状）**：非标件工时靠估，估算偏差直接变成交期风险和成本偏差
- **人机分工**：AI 出路线与工时区间；工艺工程师定稿
- **待确认**：现行工艺路线由谁制定？工时数据是否有历史记录？

#### Q15 · 下料排版与钢材利用率优化
**难度** 中 ｜ **见效** 中 ｜ **验证状态** 【行业已验证】

- **输入**：下料清单（件号、尺寸、材质、数量）
- **判断规则**：套排优化 → 给出利用率更高的排版方案与余料去向建议
- **交付物**：排版方案 + 利用率对比（优化前/后）+ 余料登记表
- **卡点（现状）**：钢材是最大成本项，利用率每提高 1% 都是净利润
- **人机分工**：AI 出方案；下料班组按实际设备能力确认可执行性
- **待确认**：现行排版方式（人工 / 软件）？钢板规格采购习惯？

### 岗位五 · PMC

#### Q16 · 急单可接性评估
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【行业已验证】

- **输入**：订单交期要求 + BOM + 库存 + 在制工单 + 产能负荷

### 岗位八 · 现场安装调试与售后

#### Q25 · 故障树匹配与排查指引
**难度** 中 ｜ **见效** 快 ｜ **验证状态** 【公开事实】（1000+ 台设备分布全国及海外）

- **输入**：现场人员的照片/视频 + 文字或语音描述（往往很模糊）+ 设备型号
- **判断规则**：现象 → 匹配故障树（**现象 → 可能原因 → 排查步骤 → 解决方案 → 所需备件**）。例：异常振动 → 轴承磨损 / 叶轮不平衡 / 基础松动 / 传动对中不良 → 按由简到难排序排查
- **交付物**：排查指引（分步 + 判断分支 + 所需工具）+ 备件清单（链接 Q26）+ 客户母语版本（链接 Q28）
- **卡点（现状）**：**现象描述不清 → 工程师远程猜 → 猜错就飞过去**，一次不必要海外出差可能等于该客户全年利润
- **人机分工**：AI 匹配与生成指引；**现场/服务工程师执行排查并回传结果**
- **待确认**：⚠️ 历史服务记录目前的形式（纸质工单/微信/口头）？**故障树必须有真实服务记录做原材料，否则就是编的**

- **交付物**：备件选型单（含替代方案与价格）
- **卡点（现状）**：老型号的备件号、可替代件**只有老师傅记得**，人一退休就断档
- **人机分工**：AI 匹配；老师傅做知识贡献者（把自己的记忆变成知识库的原材料）

#### Q27 · 上门与否的判断辅助

#### Q28 · 多语种服务沟通

#### Q29 · 服务工单归档与知识回流

- **判断规则**：招标要求 → 匹配素材 → 自动拼装成标书骨架 → 标注缺失项
- **交付物**：标书初稿 + 素材缺口清单
- **卡点（现状）**：每次投标都从零整理资质与案例，最耗时的部分还是最没技术含量的部分
- **人机分工**：AI 拼装；**国际业务负责人补充针对性内容**
- **待确认**：现有资质与业绩资料的电子化程度？

### 岗位十二 · 市场与管理层

#### Q39 · 政策情报雷达与客户机会匹配
**难度** 低 ｜ **见效** 快 ｜ **验证状态** 【公开事实】｜ **投入产出比最高**

- **输入**：生态环境部及各省生态环境厅公开信息（危废名录修订、"点对点"定向利用试点批复、排放标准制修订、危废利用处置能力公告）
- **判断规则**：关键词监控（铝灰 / 定向利用 / 豁免 / 排放限值）→ 命中即结构化拆解为"**适用范围 / 生效时间 / 对客户的影响 / 对应的蓝威产品线**" → 关联该省在册铝加工与再生铝企业 → 生成沟通材料
- **交付物**：政策周报 + 客户改造机会清单 + 现成的客户沟通材料
- **卡点（现状）**：政策信息靠业务员偶然看到，或等客户告知；响应以周计
- **人机分工**：AI 监控与生成；**销售执行触达**
- **待确认**：销售例会是否已有固定的信息同步环节可以承载这份周报？
- **为什么值得做**：这类信息 **100% 公开，无版权与保密风险**，一个人配合 AI 就能维持全流程。**投入最小、杠杆最大**

#### Q40 · 客户复购与流失预警
**难度** 中 ｜ **见效** 中 ｜ **验证状态** 【推演假设】

- **输入**：1000+ 家客户的设备档案、服务工单频次、采购周期、行业景气信号
- **判断规则**：①复购信号（设备使用超过 N 年、同行已升级、政策要求改造）②流失预警（服务响应变慢、客诉上升、长期无接触）
- **交付物**：客户经营清单（分"该联系/该升级/该警惕"三类）+ 联系话术
- **卡点（现状）**：1000+ 家客户是护城河，但**没人系统经营存量**，全靠业务员记忆
- **人机分工**：AI 识别信号；**销售执行联系，客户关系判断必须由人做**
- **待确认**：客户信息的完整度？是否有客户分级机制？

## 六、首批建议启动的 4 组场景

40 条不能一起上。按"见效速度 × 数据可得性 × 不涉密"三条标准，建议首批做这 4 组：

### 第一批 · 售前报价链（Q01 → Q02 → Q05 → Q07 → Q08）

**为什么是它**：四个岗位接力的一条完整链，是**全公司最贵的一条链**（10 余人设计团队的产能瓶颈就在这里），也是**唯一一条投了立刻见效、且效果可量化**的链。

```
客户询价
   ↓
Q01 校验信息完整性 ──→ 缺什么当场标红，生成追问清单（省掉 2—3 轮来回）
   ↓
Q02 销售自助估价 ──→ 客户随口一问，不用占技术部
   ↓
Q05 工况→选型 ──→ 老工程师的经验变成可核对的表
   ↓
Q07 成本区间（行情联动）──→ 不再用三个月前的价格报价
   ↓
Q08 三档报价 + 成本红线校验 ──→ 人确认，机器算
```

**成功判据**：单次报价的技术投入从 2—3 人天压到 0.5 人天以内；**报价模型预测误差在 3 个月内出现可观测的收敛**。
**不涉密**：报价链不碰设计图纸，可以先用云端工具跑通，**这是它能排第一的隐藏原因**。

### 第二批 · 设计资料检索（Q09）

**为什么是它**：门槛最低、见效最快，且能立刻验证"历史资料到底能不能被机器读懂"这个前提。
如果 Q09 跑不通（比如图纸全是纸质、或者存储极其混乱），那么 Q10、Q11、Q14 全都要重新评估——**这是整条设计侧路线的探针**。

**成功判据**：工程师能只靠自然语言找到 80% 以上的历史资料，不再翻文件夹。
**约束**：必须在**本地或私有云**部署，图纸不出内网。

### 第三批 · 售后故障树（Q25 → Q26 → Q28 → Q29）

**为什么是它**：1000+ 台设备的服务半径是**已经发生并持续发生的成本**，不是潜在风险。一次不必要的海外出差可能等于该客户全年利润。

**成功判据**：不必要现场出勤下降；一次解决率提升。
**前提**：需要把历史服务记录清洗成故障树的原材料。**如果历史记录是纸质或口头，这一批要先做数据整理，周期会长于预期。**

### 第四批 · 政策雷达（Q39）

**为什么是它**：投入最小、杠杆最大。政策信息 100% 公开，一个人配合 AI 就能维持全流程运转。

**成功判据**：政策从发布到触达客户的周期，从"数周至数月"压到"数天内"。
**注意**：这一批看起来最"轻"，但它解决的是**时机问题**——在一个政策驱动的行业里，响应速度本身就是竞争力。

## 八、判断"知识有没有真的沉淀下来"的唯一硬指标

原报告 §7 阶段三写过一句话，这份库把它提炼成了可执行的东西：

> **报价模型的预测误差是否在持续收敛。**

逻辑是：

```
Q05 选型规则表  ──┐
Q07 成本模型    ──┤
                  ├──→ Q08 报价 ──→ 实际成交/亏损 ──→ Q30 成本归集
                  │                                        ↓
                  └──────── Q31 偏差分析 ←──────────────────┘
                              ↓
                      反哺校准 Q05 / Q07
```

**这条回路通了，模型越用越准，知识才算变成了公司资产。**
**这条回路不通，前面所有场景都只是"让文档更好看"** —— 这正是原报告 §9 提到的"非标装备 AI 落地成功率明显低于批量制造"的根因：**不是技术不行，是缺少让模型自我校准的回路。**

## 十、下一步：先做样板，不建平台

原报告的建议是"不建平台，先跑一个真实项目"。**场景库把这句话变得更具体了**：

**用 Q01 → Q02 → Q05 → Q07 → Q08 这条链，跑通一个正在进行的真实报价项目。**

理由：
- 它不碰设计图纸，**没有数据安全障碍**，可以用最轻的工具开始；
- 它有明确的对照物（历史同类项目的耗时与质量）；
- 它的产出物（选型配置单、成本明细、三档报价）**可以直接拿给管理层看**；
- 它是 §8 那条校准回路的起点——**只有这条路跑通，后面 39 条才谈得上"值得做"**。

配套的可演示文件已经做好了，在 `场景库/样板01-询价报价/` 目录下。**里面每一份都标明了哪些是真数据、哪些是占位符——占位符必须由蓝威填。**
